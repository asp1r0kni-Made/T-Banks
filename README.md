# Т-Банк Premium — Android (APK через GitHub)

Банк-симулятор с интерфейсом «жидкое стекло», регистрацией, PIN-кодом и **своим сервером** (база данных, переводы между пользователями).
Сервер — отдельный файл `server.py` (выкладывается на PythonAnywhere, инструкция в начале файла).

### Первый запуск
1. Выложите `server.py` на PythonAnywhere (шаги — в комментарии в начале файла).
2. Откройте `app/src/main/assets/www/config.js` и впишите адрес: `https://ВАШЛОГИН.pythonanywhere.com`
   (или оставьте как есть и введите адрес в приложении: экран входа → «Сервер»).
3. Дальше — сборка APK, как описано ниже.

## Как получить APK (5 минут)

1. Создайте на GitHub **новый репозиторий** (лучше **Public** — см. ниже, почему).
2. Загрузите в него **всё содержимое этой папки** (включая скрытую папку `.github`).
   - Через сайт: *Add file → Upload files*, перетащите все файлы и папки.
   - Или через git: `git init && git add . && git commit -m "init" && git branch -M main && git remote add origin <URL> && git push -u origin main`
3. Откройте вкладку **Actions** → дождитесь зелёной галочки (≈3–5 мин).
   Если сборка не запустилась сама: Actions → *Build APK* → **Run workflow**.
4. Откройте **Releases** (справа на главной странице репозитория) → скачайте `TBank-Premium.apk` → установите на телефон
   (разрешите «Установку из неизвестных источников»).

## Как выпускать обновления (без переустановки)

1. Меняйте интерфейс в `app/src/main/assets/www/` (css/js).
2. Сделайте commit в ветку `main` (можно прямо на сайте GitHub: открыть файл → ✏️ → Commit).
3. GitHub сам соберёт новый APK и создаст новый Release (`v2`, `v3`, …).
4. В приложении: **Профиль → Обновление приложения**. Оно найдёт новую версию, скачает и установит **поверх** — данные (карты, баланс) сохраняются.
   Проверка также идёт автоматически при каждом запуске: появится уведомление «Доступно обновление».

### Почему обновление ставится поверх, а не «как новое»
Android обновляет приложение, только если совпадают три вещи:
- одинаковый `applicationId` (`com.tbankpremium.app`) — не меняйте;
- **одинаковая подпись** — ключ лежит в `signing/release.jks` и используется во всех сборках;
- растущий `versionCode` — workflow ставит номер запуска (`github.run_number`) автоматически.

> ⚠️ Не удаляйте `signing/release.jks` и не меняйте пароли. Если ключ поменяется — Android потребует удалить старую версию.
> ⚠️ Не удаляйте и не пересоздавайте репозиторий: нумерация версий начнётся с 1, и телефон не примет «более старую» сборку.

## Репозиторий Public или Private?
Автообновление читает GitHub Releases без токена, поэтому репозиторий должен быть **Public**.
Ключ `signing/release.jks` в публичном репозитории доступен всем — для личного проекта это нормально.
Хотите безопаснее — храните ключ в секретах:
1. Создайте свой ключ: `keytool -genkeypair -alias mykey -keyalg RSA -keysize 2048 -validity 36500 -keystore my.jks`
2. `base64 -w0 my.jks` → вставьте в *Settings → Secrets and variables → Actions* как `KEYSTORE_BASE64`.
3. Добавьте секреты `KS_PASS`, `KEY_ALIAS`, `KEY_PASS`. Удалите `signing/release.jks` из репозитория.
(При смене ключа первое обновление придётся поставить с переустановкой — один раз.)

## Структура
```
.github/workflows/build-apk.yml   сборка + публикация Release
app/src/main/assets/www/   интерфейс: index.html, app.css, core.js, screens.js, flows.js, config.js
app/src/main/java/.../Updater.java   проверка/скачивание/установка обновлений
app/src/main/res/                    иконка (adaptive + themed), тема
signing/release.jks                  ключ подписи
icon/                                PNG-версия иконки (512 и 1024)
```
